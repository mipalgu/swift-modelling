# Integration Architecture

## Overview

```
  Desktop tool (XMI) <--- swift-ecore convert ---> Web editor (JSON)
          |                                               |
          |                                               +---> Swift app
          |                                               |     (generated types)
          +------------ ProjectManagement.ecore ----------+
                  validate, query, compare, generate
```

Every file, whatever its format, is an instance of
`ProjectManagement.ecore`. Each tool reads the format it knows, and the
modelling tools translate between formats and check the results.

## Building Blocks

| Concern              | How it is done in this tutorial                         |
|----------------------|---------------------------------------------------------|
| Format conversion    | `swift-ecore convert` with `-m ProjectManagement.ecore`  |
| Validation           | `swift-ecore validate` against the metamodel            |
| Queries              | `swift-aql query` on XMI or JSON files                  |
| Web view             | ATL transformation `ProjectToAPI.atl` to `ProjectAPI`   |
| Swift types          | `GenerateSwiftModels.mtl` applied to the metamodel      |
| Change detection     | `swift-ecore compare` of two versions                   |
| Consistency rules    | ATL refining transformation `ReconcileProject.atl`      |
| Round-trip fidelity  | XMI to JSON to XMI, then `swift-ecore compare --exit-code` |
| APIs                 | REST, Swift client and event code generated with MTL    |

## Data Flow Patterns

### Desktop tool to web editor
1. The desktop tool saves `project-data.xmi`.
2. `swift-ecore convert` writes `project-data.json`.
3. `swift-ecore validate` checks the JSON against the metamodel.

### Web editor back to the desktop tool
1. The web editor saves `updated-project-data.json`.
2. `swift-ecore validate` rejects files that break the metamodel.
3. `swift-ecore compare` lists what changed since `project-data.xmi`.
4. `ReconcileProject.atl` restores the rules of the domain.
5. `swift-ecore convert` writes XMI for the desktop tool.

### Web editor to the Swift app
1. `GenerateSwiftModels.mtl` generates Swift types from the metamodel.
2. The app decodes the JSON files with `JSONDecoder`.

## Directory Layout

```
integration/
  ProjectManagement.ecore     shared metamodel
  ProjectAPI.ecore            compact web view
  project-data.xmi            desktop tool data
  project-data.json           converted for the web editor
  updated-project-data.json   edited in the web editor
  web/                        ProjectAPI view for web clients
  swift-models/               generated Swift types
  sync/                       reconciled and round-tripped models
  api/                        generated REST, client and event code
```
